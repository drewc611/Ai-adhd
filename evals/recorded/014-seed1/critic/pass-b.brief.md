The\nprocess is alive, so the lock is held, so every subsequent cron firing exits immediately and\nquietly with status 1. The overlap is cured perfectly. So is the work. Mutual exclusion\npromised that two runs would not overlap. It never promised that one run plus the corpse of\nanother would be safe, and that is the actual failure mode people see.\n\n3. ### MECHANIC

```yaml
problem_hash: "sha256:bad9dcb705701f121abe594852d98e034d4dfafb48439d844790bfa72068519e"
frame: "MECHANIC"
position: "Delete the cron entry and run the script under a supervisor that starts the next execution only after the previous process has exited, with a hard kill timeout on each execution."
reasoning: "1. The physical components, and what each does while the system waits.\n\nA cron daemon sleeps on a timer and wakes at a wall-clock boundary. On waking it forks a shell,\nthe shell execs a Python interpreter, and the interpreter opens whatever it opens: a database\nconnection, one or more sockets, temp files, maybe a log file. Then it blocks on the slowest of\nthose. While it blocks, the cron daemon is doing exactly one thing: sleeping until the next\nboundary. It does not read the process table, it does not wait on the earlier child, and nothing\nabout that child's state reaches the decision to fork again. There is no component in this\nsystem whose job is to know that the last run is still alive. That is the whole of the defect.\nThe overlap is not a failure of the script; it is the absence of a part.\n\n2. What is held, consumed, or leaked during the interval.\n\nPer live copy: a process slot, the resident memory of an interpreter plus everything it imported\nand every row it buffered, one or more connections against a pool with a fixed ceiling, file\ndescriptors, any temp file written but not yet renamed into place, and any rows locked by an\nopen transaction. Two copies touching the same rows each wait on the other's locks, so each runs\nslower than one copy would. Run N+1 therefore takes longer than run N, which makes it more\nlikely to still be alive when run N+2 fires. The overlap feeds itself.
```
